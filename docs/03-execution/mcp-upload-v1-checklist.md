# MCP 商品上传第一版执行清单（V1）

版本：v1.0  
日期：2026-04-03（Asia/Shanghai）

## 0. 本版目标

在不追求全自动提审/上架的前提下，先实现：
1. 从标准商品数据读取“基础信息”。
2. 通过 Chrome-MCP 自动填入小红书商品管理页面。
3. 完成“保存草稿/创建商品”并输出执行日志。

本版不做：
1. 全自动审核通过闭环。
2. 无人值守批量上架。

---

## 1. 输入规范（必须先准备）

## 1.1 商品基础字段（最小集）
1. `external_id`：外部商品ID（你侧唯一键）
2. `product_name`：商品名称
3. `short_name`：商品简称
4. `brand_name`：品牌名
5. `category_path`：分类路径（末级类目）
6. `spec_name_1`：规格名（如“颜色”）
7. `spec_value_1`：规格值（如“黑色”）
8. `barcode`：条码
9. `price`：售价
10. `original_price`：划线价
11. `main_images`：主图URL列表（逗号分隔）
12. `desc_text`：商品描述纯文本

## 1.2 文件格式
1. 推荐 `CSV UTF-8`。
2. 每行一个 SKU（同 SPU 可多行，使用 `external_id` 归并）。
3. 图片链接必须可公网访问且符合官方尺寸/大小要求。

---

## 2. 第一步：环境与账号准备

1. [ ] 准备独立 Chrome Profile（仅用于店铺自动化）。
2. [ ] 手动登录小红书商家后台并确认有“商品管理”权限。
3. [ ] 在本机确认 Chrome-MCP 可稳定执行：`打开页面/点击/输入/上传图片/截图`。
4. [ ] 建立日志目录：`logs/upload/` 与截图目录：`artifacts/upload/`。

验收标准：
1. MCP 连续执行 20 次基础动作无中断。
2. 页面会话可持续 30 分钟以上。

---

## 3. 第二步：页面探测与选择器基线（一次性工作）

1. [ ] 进入“商品管理 > 新建商品”页面。
2. [ ] 提取并记录关键控件选择器（主选择器 + 备用选择器）：
   - 类目选择
   - 品牌输入
   - 商品名称/简称
   - 规格区域
   - 价格区域
   - 主图上传
   - 商品描述
   - 保存草稿/提交按钮
3. [ ] 为每个控件建立“定位优先级”：
   - `data-*` / 稳定属性 > 文本锚点 > 层级路径
4. [ ] 保存一份页面结构快照（用于后续改版比对）。

验收标准：
1. 单页关键控件定位成功率 >= 98%。
2. 任一控件失效时可通过备用选择器恢复。

---

## 4. 第三步：单商品上传流程（MVP 主流程）

对每个 `external_id` 执行：

1. [ ] 打开“新建商品”页面并等待关键文本出现。
2. [ ] 填写分类（或选择到末级类目）。
3. [ ] 填写品牌并从候选中选择。
4. [ ] 填写商品名称与简称。
5. [ ] 填写规格信息（至少一组 SKU）。
6. [ ] 填写价格/划线价。
7. [ ] 上传主图（至少1张，建议3-5张）。
8. [ ] 填写商品描述。
9. [ ] 点击“保存草稿/创建”按钮。
10. [ ] 读取页面成功提示并截图归档。
11. [ ] 记录结果到执行日志（成功/失败、失败原因、页面证据）。

验收标准：
1. 单商品成功率 >= 90%（首版）。
2. 失败任务都能给出可定位原因（字段、控件、网络、权限）。

---

## 5. 第四步：批量执行与风控控制

1. [ ] 批量调度按“串行 + 限速”执行（首版不并发）。
2. [ ] 每个商品间隔 3~8 秒随机等待。
3. [ ] 每 10 个商品强制刷新会话健康检查（页面可交互、按钮可点）。
4. [ ] 连续失败 3 次触发自动暂停并告警。
5. [ ] 高风险动作（正式提交审核/上架）默认关闭，仅人工确认后启用。

验收标准：
1. 50 个商品批跑过程中不出现账号异常弹窗。
2. 暂停/恢复机制生效，且无重复提交。

---

## 6. 第五步：审计与可追溯（必须）

每条任务输出：
1. [ ] `task_id`、`external_id`、开始/结束时间。
2. [ ] 关键步骤耗时（打开页面、上传图片、提交）。
3. [ ] 页面提示文案原文。
4. [ ] 关键截图路径。
5. [ ] 错误码（自定义）与错误归类（定位失败/校验失败/会话失效/平台拦截）。

验收标准：
1. 任一失败任务可在 3 分钟内定位到失败步骤。
2. 任一成功任务可回放核心证据链。

---

## 7. 回滚与重试规则

1. [ ] 若“提交前”失败：允许直接重跑该商品。
2. [ ] 若“已提交但返回未知状态”：先查商品列表是否已创建，再决定重试。
3. [ ] 严禁盲目重复创建；必须按 `external_id` 做幂等判断。
4. [ ] 对“选择器失效”错误：先切备用选择器，再人工介入更新规则。

## 9. 建议节奏（5个工作日）

1. Day1：字段模板 + 页面探测 + 选择器基线。
2. Day2：打通单商品上传（不含图片批量优化）。
3. Day3：接入图片上传与日志归档。
4. Day4：批量调度 + 暂停恢复 + 失败重试。
5. Day5：灰度跑 20~50 个商品并修复问题。

## 10. 下一版（V1.1）升级方向

1. 增加“提交审核”自动化（审批门控）。
2. 增加“上架开关”自动化（仅审核通过后触发）。
3. 将“品牌/类目/属性值”切到官方 API 预校验，减少 UI 失败率。
