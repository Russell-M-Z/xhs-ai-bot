# 能力建设计划（MCP 商品上传）

版本：v1.0  
更新时间：2026-04-03（Asia/Shanghai）  
责任模块：orchestrator-api / chrome-mcp-worker / rule-engine

## 建设框架

按四层推进：
1. `L1 任务编排层`：任务状态机、批量调度、重试/熔断
2. `L2 执行适配层`：Chrome-MCP 原子动作、选择器治理、页面容错
3. `L3 业务规则层`：字段校验、风险门控、审批开关
4. `L4 观测审计层`：日志、截图、报表、运行手册

---

## 阶段里程碑

## 阶段 A（V1，1周）
目标：跑通“基础信息上传到商品管理页并保存草稿”。

交付：
1. 单商品上传主流程。
2. `selector-map` 机制（主/备选择器）。
3. 批量串行执行与失败暂停。
4. 执行日志与截图归档。

验收：
1. 单商品成功率 >= 90%。
2. 失败可定位率 100%。

## 阶段 B（V1.1，1-2周）
目标：提升稳定性并接入“提审门控”。

交付：
1. 自动提交审核（默认人工确认后执行）。
2. 幂等机制（external_id 去重）。
3. 异常分类与自动重试策略。

验收：
1. 批量 50 条任务稳定跑通。
2. 重复创建率为 0。

## 阶段 C（V2，2-4周）
目标：API + MCP 混合架构，增强长期可维护性。

交付：
1. 品牌/类目/属性改为 API 预校验。
2. 核心创建链路优先 API，MCP 做 UI 补位。
3. 审批中心与报表中心上线。

验收：
1. 上传成功率 >= 95%。
2. 页面改版导致的故障恢复时间 < 1 天。

## 能力建设任务清单（按模块）

## orchestrator-api
1. 建立任务模型与状态流转。
2. 增加批次调度、失败暂停、恢复机制。
3. 输出批次执行报告。

## chrome-mcp-worker
1. 封装标准动作：打开页面、填充、上传、点击、等待、截图。
2. 建立 `selector-map.json` + fallback 执行策略。
3. 增加“步骤级重试”和“页面健康检查”。

## rule-engine
1. 商品字段必填与格式规则校验。
2. 风险动作开关（提审/上架）。
3. 错误分类码与拦截策略。

## docs/runbook
1. 维护字段模板、执行清单、故障手册。
2. 每次迭代更新能力矩阵状态。
3. 复盘问题并沉淀处理 SOP。
